01 — What it does

Running the repository is not the same as reproducing the paper. The experiment, the metric, and the scientific settings are scattered across the article, the appendix, and the code, and those sources often disagree.

Repo2Reproduce starts from the paper and its official repository. It freezes one contribution-grounded result, reconciles the settings in both directions, prepares a ROCm environment, and runs the experiment under a controller that owns completion. Success is a comparison with the exact paper target, not a clean exit.

Reproduction is recovering the experiment before it is a problem of running code.
Why a README command is not enough

02 — System

Freeze the claim. Then run it.

A paper and a repository URL go in. A target contract, a configuration audit, an execution package, and a verdict come out: match, miss, incomplete, or review.

Reconcile

Both directions.

Map every paper requirement into the code, and every scientific input the code consumes back to the paper. When they conflict and the code can express it, the paper value wins.

Repair

The smallest fix.

A failed run gets a targeted operational correction. The selected experiment, dataset, metric, and aggregation stay untouched. The retry budget is two.

Report

The paper’s number.

Compare the extracted result with the exact target, including a named baseline when the claim is an improvement. Near is not the same as matched.

CUDA paths use a porting ladder: an existing ROCm implementation, a portable path already in the repository, HIPIFY with repairs, then a targeted kernel rewrite. A port counts only after a numerical-parity check. Parity is not a claim about speed.

03 — Results

The paired core is 20 papers from ICML, ICLR, NeurIPS, and ACL 2025, each runnable on one AMD Instinct MI355X within four hours. The baseline leaves 3 runs incomplete. Repo2Reproduce finishes every core task, so the share of runs that produce a paper-comparable result rises from 85% to 100%. A scalar match uses a 5% relative-error rule, and a claim of improvement must still beat the paper’s baseline.

On GrokFormer, accuracy landed at 88.90 against the paper’s 89.57. That is inside the 5% band, but it no longer exceeded the reported 89.23 baseline, so the system recorded a miss.

The two kernel-porting tasks, NSNQuant and SageAttention, both meet their numerical-parity criteria. Performance agreement is reported separately: the papers measured NVIDIA hardware, and these runs use an MI355X.
